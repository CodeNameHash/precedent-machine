# Reusable mechanism inventory

Date: 2026-08-08. Scope: `lib/canonical-v2/` and
`lib/canonical-v2/native-producer/`, cross-checked against committed
evidence under `evidence/canonical-v2/*/resolution.json` and
`evidence/canonical-v2/*/review-queue.json`, and against which
`native-producer/*-producer-prompt.js` files actually declare a mechanism's
input fields (`grep -rn` over `lib/ scripts/ pages/ tests/`, never a
comment-only match).

**Method note on "fires in practice."** A field being declared in a producer
prompt proves the model is *asked*. A grep hit inside `candidate-resolution.js`
proves the resolver *calls* the mechanism. Neither proves the mechanism's
full effect is materialising in real runs. Where I could distinguish these
(limb-components.js, below) I have, because the gap between "wired" and
"visibly changing an outcome" is exactly the kind of claim this programme has
gotten wrong before.

## 1. Wire it up — general, working, simply not connected

Ranked by value (symptom counts fixed) over cost.

1. **`qualifier-attachment.js` → INTERIM_OPERATING.** Replace `ioc-mechanic-resolution.js`'s exact-quote-match attachment (`limbAttachment`) and 4-regex chapeau detection (`parentAttachment`/`parentWideLanguage`) with the same POSITION-only ask (CHAPEAU/ITEM/TRAILING) already proven live on REPRESENTATIONS (5/37/4 real occurrences in one deal's evidence alone). Directly targets **`IOC_ATTACHMENT_TARGET_QUOTE_MISSING` (171)** — the single largest symptom count in the whole inventory — and **`IOC_PARENT_ATTACHMENT_SCOPE_UNCORROBORATED` (59)**. The mechanism does not need to be built; it needs a new producer-prompt field and a resolver rewire.

2. **`limb-components.js` → TERMINATION.** TERMINATION's own producer prompt requires the model to restate `terminating_party` verbatim inside the same narrow quote as the grant/cure-period fact it's attached to (mirroring the exact "restate the label inside your own narrow quote" failure mode `mae-clause-label-parse.js` and the limb tree were built to avoid). Wiring the limb identity tree so a terminating party can be declared once at a chapeau/grant-stem node and inherited by its cure period, instead of demanded fresh in every quote, targets **`TERMINATING_PARTY_REF_NOT_IN_QUOTE` (60)**. Caveat: verify the tree-consumption path actually populates on a live corpus before counting on it — see the table's "Fires in practice" note; MAE_DEFINITION and REPRESENTATIONS both show `limb_component_trees: []` in every committed run today, so this needs a proof run, not just a prompt change.

3. **`mae-clause-label-parse.js`'s verification pattern → any family gaining a `clause_label`-shaped field.** Lower priority than 1-2 because it requires a producer-prompt design change before the existing code even applies; but the three-tier algorithm (self-contained / source-adjacent / sibling-contained) is a proven, general answer to "does this label denote this quote's position," directly reusable once TERMINATION or INTERIM_OPERATING need the same question answered for their own enumerated sub-items.

4. **`qualifier-kind-lexicon.js` → any family that adds a structured qualifier `kind` field.** Already fully deployed to its current addressable surface (2 of 2 families that ask for `kind`); the opportunity is prompt-level, not code-level — GENERAL_COVENANTS and NO_SHOP both narrate knowledge/materiality qualifiers in free text today without a structured field to route through this classifier.

## 2. Exists but broken or dormant

1. **`family-absence-coverage-attestation.js` — defined, exported, called nowhere.** The single clearest finding in this sweep: zero production callers, zero test files, only a bare path string inside an unrelated inventory list. It is also internally incomplete by its own design (`requireTrustedAbsenceEvidence` always throws `TRUSTED_FAMILY_ABSENCE_EVIDENCE_VERIFIER_UNAVAILABLE`, because no issuer for that evidence exists anywhere in the codebase). Reviving it requires building the missing issuer before the first real call site can succeed — this is a genuine gap, not a quick wire-up.

2. **`limb-components.js`'s tree-consumption path — wired, called, unproven.** Distinct from the module being "dormant": the code runs, but `limb_component_trees` is `[]` in all 9 committed MAE_DEFINITION runs and every committed REPRESENTATIONS run checked, and the fallback reason `LIMB_PATH_NOT_IN_TREE` has zero occurrences anywhere in evidence either. Either the pre-pass conditions that populate the tree are not being met by real compiled candidates yet, or the qualifiers currently reaching resolution never take the ITEM/TRAILING-with-`governs_path` branch that would exercise it. Worth a direct instrumentation check before generalising further, and before trusting it to solve TERMINATION's problem (recommendation 2 above).

3. **`qualifier-attachment.js` → CAPITALISATION.** Fully wired (the family that originated it), but CAPITALISATION extraction is currently parked per the task brief, so this half of the mechanism's own footprint is not running against anything today. Not broken — just currently pointed at a family that isn't being extracted.

## 3. Genuinely family-specific — do not generalise

- **`sole-remedy-resolution.js`** — the `REM-SOLE` concept (sole-remedy clauses, FRAUD/WILLFUL_BREACH carveouts) is a legal concept that exists only in remedies drafting. Nothing to reuse elsewhere.
- **`ioc-corroboration.js` / `guaranty-corroboration.js` / `general-covenant-corroboration.js` / `tax-cooperation-corroboration.js`** — same code *shape* (category-to-regex lexicon) repeated four times, but the actual regex vocabulary in each is a different family's legal terms of art (capex vs. guaranty release conditions vs. tax cooperation covenants). Sharing the harness would cut duplication; sharing the content is not meaningful — a CAPEX regex has no business classifying a guaranty release.
- **Modiv-specific sidecars** (`modiv-termination-fee-payment-timing-parser.js`, `modiv-termination-fee-source-parser.js`, `structured-per-share-cash-source-parser.js`/`structured-per-share-cash-value.js`) — single-deal pilot scaffolding, already catalogued in `docs/core/GRAVEYARD.md` entries covering the Modiv termination-fee pilot; do not re-investigate these as generalisation candidates, that ground is already covered.
- **`no-other-reps-fraud-resolution.js`'s containment logic** — checked and confirmed wired (via `no-other-reps-fraud-dark-bridge.js`, `no-other-reps-fraud-product-projection.js`, `review-preview-assembly.js`, and 6 test files); its containment rules are built around NO_OTHER_REPS_FRAUD's own specific disclaimer/reliance clause shape and were not found to generalise on inspection.
