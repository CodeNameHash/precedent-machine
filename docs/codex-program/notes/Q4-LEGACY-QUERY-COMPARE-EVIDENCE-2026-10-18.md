# Q4: legacy Query and Compare against the layered published-facts read

Evidence for Ben's one-line decision on plan item Q4 ("Decide with Ben whether legacy Query and Compare migrate to this read or are retired"). Read from the repository at commit 3ab0989 on 2026-10-18 by implementer C; no code changed for this note. File and line references are to that commit.

## The decision in one line

Legacy Query is already switched off at every entry point and reads tables the product path does not write; Compare is two extra columns on the legacy review page reachable only by typing a URL, with its market data switched off. Neither consumes anything the layered read provides, and the layered read today serves only activated releases, of which the preview branch holds none. The choice is between retiring both now (deleting about 36,000 lines of code and registry that nothing routes to, plus 80 test files outside `test:active`) and keeping them unrouted until a Query on layered facts exists. Migrating them is not a third option: there is nothing to migrate, because their inputs (legacy `provisions.ai_metadata.features`) do not exist for a V2 run.

## 1. What legacy Query consumes today

- **Every API route is a stub.** `pages/api/query/run.js`, `interpret.js`, `kinds.js`, `field-options.js` and `demo-set.js` each re-export `queryContainedHandler`, which answers 503 `ROUTE_CONTAINED` (`lib/query-containment.js:1-41`). `/api/saved-queries` and `/api/canonical-v2/query` are contained the same way.
- **Every page redirects.** `pages/query/index.js:16-23`, `pages/query/[kind]/[id].js:74-81`, `pages/query/whats-market/adhoc.js:8-11` and `pages/query/process/pilot.js:17-21` redirect to `/` from their server-side props. The home page hides its query surface behind `QUERY_UI_CONTAINED = true` (`pages/index.js:34`, `:355`, `:450`).
- **The archived handlers** live under `lib/query/contained-routes/*.js` and read the legacy tables only: `deals` (id, acquirer, target, value_usd, announce_date, sector, metadata), `provisions` (id, deal_id, type, category, full_text, ai_metadata, created_at; the whole corpus in pages of 1,000 with a 60-second per-instance cache, `lib/query/context-cache.js:13-89`), `provision_cards.provenance` (`lib/query/prov.js:88-89`), `saved_queries` and `users` (`contained-routes/saved-queries.js`). No Supabase RPC; no `product_*` table; the grep for `product_` and `published` across `lib/query`, the query pages, the compare components, `lib/feature-compare.js`, `lib/row-market-stats` and `lib/market-metrics` returns nothing.
- **Its data model** is the legacy card: field values come from `provision.ai_metadata.features` (`lib/feature-compare.js:69-76`), keys resolve through the 698-entry alias registry `lib/query/serving-registry-v1.json` (`lib/query/resolve.js:80-111`), and 17 provision card types map to family codes (`lib/query/types.js:21-59`). A query is refused when a provision is `VALIDATED_NOT_SERVED` (`lib/query/engine.js:51-54`).
- **Three query kinds** remain in the engine (`lib/query/types.js:7-17`, `engine.js:55-57`): `PROVISION_CROSS_CUT`, `MARKET_RANGE`, `FILTER_THEN_LIST`. `DEAL_COMPARE` and `DEAL_TO_MARKET` were retired as kinds (their executors remain as files; tests assert the engine throws `invalid query_kind` for them, `tests/query/wp-query.test.js:122-136`).
- **A model call** in interpret only: `contained-routes/interpret.js:54-67` calls the Anthropic client with forced tool use, falling back to a deterministic parser (`lib/query/natural-language.js:918`).

## 2. What legacy Compare consumes today

- **Where it renders.** Not a page and not a query kind: extra columns on the legacy review page `pages/review/[id].js` when the URL carries `?compare=<dealId>[,<dealId2>]` (at most three, `components/review-v2/compareData.js:31-47`) or `?market=1` (`pages/review/[id].js:42-46`, `:337-346`). The `deal-compare` link the home page builds in pick mode (`pages/index.js:372-377`, `:578-581`) goes to the contained `/query/deal-compare/adhoc`, which redirects to `/`. No code builds a `/review/<id>?compare=` link; the columns are reachable only by typing the URL.
- **What it reads.** `useComparedDeals` calls `/api/deals?id=…&view=header` and `/api/review/<id>/cards` (`compareData.js:215-216`); the cards route reads `transaction_steps`, `claims`, `deals`, `provisions` and `provision_cards` (`lib/queries/review-deal.js:233-416`). These routes are not contained.
- **Market data is off.** `legacyMarketStatsContained = true` on the review page (`pages/review/[id].js:341`, `:366`, `:380`); `/api/market-stats` answers 503 (`pages/api/market-stats.js`, `lib/market-stats-containment.js`); `/api/corpus-stats`, `/api/compare/features`, `/api/compare/rep-materiality` and `/api/comparisons` are broad-corpus contained (`lib/broad-corpus-containment.js:1-25`). `useDealToMarket` calls a contained route for a retired kind (`compareData.js:420-448`).
- **Its field schema** is the same legacy `ai_metadata.features` model as Query.

## 3. What the layered published-facts read provides

- **Route.** `pages/api/product/published-facts.js:11-29`, authenticated (session cookie or the internal bearer token), returns `{ schema_version: 'PRODUCT_PUBLISHED_FACTS/V1', agreements }`. Filters: `family` and `subtype`, exact matches applied in memory after a full read. No deal, date, party or value filter; no paging; no text search.
- **Store.** `ProductPhase3Store.listPublishedLayeredFacts` (`lib/product/phase-3-store.js:80-109`) reads three tables with plain selects: `product_agreement_release_heads` (source_document_id, release_id), `product_agreement_releases` (release_id, source_document_id, run_id, summary, published_at) and `product_source_documents` (source_document_id, retrieval_url). It does not read `product_proposals`, `product_fact_components` or `product_fact_conclusions`: the facts come from `release.summary.families[].facts`, keeping only those with a `components` array (V1 facts are dropped).
- **Which agreements.** The current release head per source document, so activated releases only; draft runs are not served. The preview branch holds zero release heads and zero releases on 2026-10-18 (read with one SQL count on `ecrtoofsyxozazkvsvcl`), so the route answers an empty list today. The first content arrives with Phase 6's inactive release load and activation.
- **Per agreement.** `run_id`, `source_document_id`, `agreement_label` (the retrieval URL), `released_at`, `facts`. No deal id, party names or signing date; `product_source_documents` has no `deal_id`, so there is no link to the legacy `deals` table.
- **Per fact** (contract `contracts/product/fact-components.v2.json`): `fact_id`, `family_key`, `subtype_key`, `headline { label, distinguishing_component_ids, summary }`, `components[]`, `coverage_only`; stored facts also carry `section_reference` and, when a V9 run wrote them, `conclusions { table_key, row_label, cells }` (read by `lib/product/table-view.js` `hasReadout`). Whether a real release summary carries `conclusions` was not verified: there is no release to read.
- **The page.** `pages/query/provisions.js` (142 lines): family and subtype selects from `legal-schema.v2.json`, one `PublishedSummary` per agreement in the table layout (`buildTableView` from `lib/product/table-view.js`), linked only from `pages/review/index.js:39` ("Query published provisions"). Test: `tests/product-published-facts-query.test.js`, in `test:active`.

## 4. Entry points and tests

- The app chrome links to `/` and `/library` only (`components/chrome/AppHeader.jsx:14-21`, `TopBar.jsx:21-26`). The product Review pages (`pages/review/product/**`, `components/product/*`) link to no `/query`, deal compare, `/deals` or `/provisions` route and import none of `lib/query`, `feature-compare`, `market-metrics`, `row-market-stats` or the review-v2 compare files.
- `npm run test:active` (59 files) includes none of the 80 test files that mention legacy Query, Compare or the market libraries; the full `npm test` runs them all.
- Lines: `lib/query/**` 24,274 (18,170 of them the alias registry JSON, 5,500 JavaScript); `components/query/*` 1,643; the review-v2 compare and market files 4,251; `lib/feature-compare.js` 634; `lib/row-market-stats/*` 3,386; `lib/market-metrics/*` 2,575. The product read path: `published-facts.js` 31, `published-layers.js` 35, `phase-3-store.js` 123, `table-view.js` 2,260, `PublishedSummary.jsx` 216.

## 5. What each choice costs

| Choice | What it means | Cost | What it does not give |
| --- | --- | --- | --- |
| Retire now | Delete `lib/query/**`, `components/query/*`, `pages/query/*` except `provisions.js`, `pages/api/query/*`, the compare and market files under `components/review-v2`, `lib/feature-compare.js`, `lib/row-market-stats`, `lib/market-metrics`, their 80 test files and the containment shims; keep `pages/query/provisions.js`. | One deletion commit plus a `npm test` and build run; the alias registry (698 legacy field names) is lost from the active tree and stays in Git history. | A Query on layered facts: the provisions page is a reader, not a query (no cross-agreement filter beyond family and subtype, no value or date filter). |
| Keep unrouted | Leave everything as it is: contained routes, redirecting pages, 80 tests outside `test:active`. | Nothing now; the code and the registry keep ageing against the V2 contracts, and every grep and audit reads through it. | Nothing either; no user can reach it. |
| Migrate | Rewrite the three engine kinds and the compare columns over `PRODUCT_PUBLISHED_FACTS/V1`. | A new field model: the kinds filter on `ai_metadata.features` keys that V2 facts do not have; the nearest V2 equivalent is a conclusions cell (`table_key`, `row_label`, `column_id`, `code` or `value`), which exists only for V9 runs and only on activated releases. The executors, registry and natural-language interpreter would be written again, not ported. | Nothing the provisions page plus a cell-level filter on conclusions would not give more directly. |

Not a lawyer decision, but a product one, so put as a question: which of retire now or keep unrouted, and whether a Query on layered facts (filtering agreements by a conclusions cell, for example every deal whose termination fee is above a percentage) should be a plan item of its own once releases exist.
