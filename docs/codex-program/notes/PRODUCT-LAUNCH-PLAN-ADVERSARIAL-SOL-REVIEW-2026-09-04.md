# Adversarial Sol review of the product launch plan

Date: 2026-09-04

Reviewer: independent GPT-5.6 Sol session. The reviewer did not write the
draft.

Verdict on first draft: `REVISE`.

## Findings and dispositions

| Finding | Disposition in final plan |
|---|---|
| The schedule total was wrong and full 25-family delivery was optimistic. | The first revision corrected the arithmetic. The final review moved the delivery target to five calendar weeks, with a measured checkpoint on day 9. |
| No durable job, retry, resume or partial state existed. | Added an asynchronous idempotent run model and per-section work states in Phase 1. |
| The dormant broad-corpus URL handler is not a valid canonical intake seam. | Replaced the reuse claim with one adapter over raw SEC capture, strict host and redirect policy, accession and exhibit identity. |
| Two section trees and a conflicting `analyseAgreement` name would remain. | Made `AgreementIndex` the only structural source and renamed the new extraction interface `buildAgreementDraft`. |
| Routing was effectively single-family when a rule matched. | Required semantic multi-label routing on every substantive section. Deterministic labels are evidence, not a short circuit. |
| The 25 current prompts do not all produce complete legal propositions. | Made the legal schema the output contract and required each prompt to be audited against it before reuse. |
| "All key provisions" had no denominator. | Set the current 25 families as the launch minimum and added a residual unusual-provision pass. |
| The fact state mixed proposals, issues, review and publication. | Separated proposals, issues, coverage assertions, fact revisions, review revisions and agreement releases. |
| Atomic facts lost legal relationships. | Added proposition groups and typed fact links. |
| The proposed source context UI did not exist. | Made a context compiler and multi-span source panel explicit Phase 2 and 3 work. |
| Review editing preceded durable draft storage. | Moved draft schema, autosave, optimistic locking and audit history into Phase 1. |
| Both unseen agreements became training data. | Split development, calibration and final blind agreements. A holdout that drives a fix is replaced. |
| A 90% acceptance rate could reward easy, incomplete output. | Added critical-fact recall, severity-weighted recall, citation sufficiency, contradiction, unresolved and maximum-review-time bars. |
| Partial results could look complete. | Added agreement-level state and a publication rule requiring all material coverage decisions. |
| Provenance was assumed to survive. | Required durable model-call records referenced by proposals and facts. |
| Removing all authority machinery could remove runtime safety. | Distinguished documentary ceremony from SEC, source, access, write, audit, backup and rollback controls. |
| One agreement was too weak for shared-core CI changes. | Added dependency-based checks: family tests for leaf changes and all-family replay for router, provider, shared resolver, schema and context changes. |
| Fresh implementers and a clock rule could optimise checklist motion rather than product progress. | Kept one continuous Sol manager, one primary Sol implementer, removed forced clock switching and locked release bars before blind evaluation. |
| Compare and Query enlarged first release without proving the summary. | Limited initial release to Review. Compare and Query follow the stable publication contract. |
| The hardest evidence came too late. | Put the legal denominator first, then a durable three-family vertical slice and calibration before scaling. |

## Challenges not adopted literally

The review correctly required a legal coverage contract. It does not require
Ben to hand-author a new 25-family specification before code starts. Codex will
derive it from existing legal work and bring Ben only real legal ambiguities.

The review correctly rejected a fixed 15-day promise. It does not justify a
new certification programme. The final plan uses one calibration agreement,
one blind agreement and one replacement holdout only if the first holdout
drives a fix.

The review correctly retained runtime integrity controls. It does not retain
M-stage authorities, transitive receipts, phase allowlists, plan hashes or
historical evidence gates. Those controls did not catch the current duplicate
queue, missing runs, synthetic rows or incomplete facts.

The first reviewer did not review the revised prose. Its material findings are
incorporated above. A separate Sol session performed the final review below.

## Final independent review of the revised plan

A second independent GPT-5.6 Sol session reviewed the revised plan and the
Deal Storylines prompt. Its verdict was `REVISE`. The final eight corrections
were:

| Finding | Final correction |
|---|---|
| The ordinary SEC URL and progress interface was missing. | Phase 3 now includes authenticated submission, live status, partial and failure handling, retry and automatic navigation to Review. |
| Source-hash idempotency would suppress intentional reruns. | Retries use a client key. Source, schema, prompt bundle, model configuration and generation identify an analysis. |
| Deterministic routing could still short-circuit AI. | Semantic multi-label routing now runs on every substantive section. Rule labels are evidence only. |
| Existing `AgreementIndex` and context code can carry old programme coupling. | Phase 0 now defines a small structure contract and reuses only pure functions that fit it. |
| The first editor had unnecessary split, merge, undo and rerun controls. | Launch actions are accept, edit, reject, add missing fact, mark unresolved and save. Revision history restores mistakes. |
| Publication could avoid review by marking text immaterial. | Every section must have a coverage state. The lawyer reviews facts and exceptions, sees all other dispositions in one coverage view and gives one agreement-level confirmation. One-agreement model metrics are diagnostic, not release claims. |
| Four calendar weeks was too aggressive after adding the missing work. | The target is five weeks. Day 9 remains the reforecast point. Family scaling is stated as parallel person-days. |
| The manager prompts could create another planning exercise. | The Sol manager adopts one checklist, updates it in place and dispatches Phase 0 immediately. Deal Storylines now does the same. |

No third review is planned. Further review is justified only by implementation
evidence, not by another reading of the plan.
