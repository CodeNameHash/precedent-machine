## Sequencing principle

Expand deals-per-frozen-concept before concepts-per-deal: the frozen
bundle's 14 concepts are the closed vocabulary; running more deals
through them creates zero taxonomy pressure. Families whose codes are
most exposed to new-deal variance come last; termination-fee expansion
WAITS for the QXO freeze-gate amendment (Ben deferred it).

## Work packets (in order)

**WP-EXP-01 — reviewed-slice harness.** Generalize the hand-built
per-deal reviewed-slice modules (landos-*/qxo-*) into a repeatable
pipeline: source text + reviewed payload in → validated claims/
relationships/rows out, with deterministic identities and quarantine for
anything unfamiliar. Deliverable: harness + tests replaying BOTH existing
deals byte-identically (the regression proof that generalization changed
nothing).

**WP-EXP-02 — no-shop family, 3-deal pilot.** NOSOL-MATCH / NOSOL-NOTICE
/ NOSOL-PROHIBIT / NOSOL-EXCEPT / NOSOL-REMATCH across three deals with
strong existing curation (candidates: Metsera, Kraft, Cooper Tire —
integration owner confirms against curation state). Reviewed payloads
are Fable-reviewed legal work, not delegated extraction. Output:
candidate rows + import plan for Ben's dry-run-first staging import.

**WP-EXP-03 — deal-relative money metrics pilot.** IOC-CAPEX and
REP-T-CONTRACTS thresholds (% of deal value) on the same three deals —
numeric normalisation, lowest vocabulary risk.

**WP-EXP-04 — QA cross-check.** Every expanded value cross-checked
against the legacy extraction for the same deal; disagreements are
findings (either legacy defect or reviewed-payload error), adjudicated
before any import plan ships. Feeds P9_SHADOW_REEXTRACTION evidence.

**WP-EXP-05 — scale-out.** Only after the pilots' candidate release
passes staging verification: remaining deals in batches, same gates per
batch. P9_SCOPE_EXACT intake-universe accounting starts here.
